SECTION 2: MCP SERVER CONFIGURATIONS & LIFECYCLE
================================================================================

Goal: Let the user configure and connect local MCP servers (e.g., SQLite, 
Postgres, GitHub, Slack) that the AI will later use as tools.

2.1 Data Model
  MCPServerConfig object (persisted globally in electron-store, NOT per-project):
    {
      id: string,               // uuid
      name: string,             // "Local SQLite Database"
      command: string,          // "npx" or "node" or "python"
      args: string[],           // ["-y", "@modelcontextprotocol/server-postgres", "postgres://..."]
      env: Record<string, string>, // { "GITHUB_TOKEN": "ghp_..." }
      autoStart: boolean,       // Connect automatically when app launches
      createdAt: number,
      updatedAt: number
    }

  MCPConnectionState:
    'disconnected' | 'connecting' | 'connected' | 'error'

2.2 mcpStore.js
  {
    servers: MCPServerConfig[],
    connectionStates: Record<serverId, MCPConnectionState>,
    serverErrors: Record<serverId, string>,
    serverTools: Record<serverId, MCPTool[]>, // Fetched after connection
    
    // Actions
    loadServers(),
    addServer(config),
    updateServer(id, patch),
    deleteServer(id),
    connectServer(id),
    disconnectServer(id),
  }

2.3 mcpHandler.js (electron/handlers/)
  Requires installing MCP SDK in package.json:
  `npm install @modelcontextprotocol/sdk`

  IPC-exposed functions:
    - mcpListServers() -> MCPServerConfig[]
    - mcpAddServer(config)
    - mcpUpdateServer(id, patch)
    - mcpDeleteServer(id) -> disconnects first if running
    - mcpConnect(id) -> 
        1. Reads config.
        2. Injects custom env vars over process.env.
        3. Initializes `Client` with `StdioClientTransport` from the MCP SDK.
        4. Spawns the process.
        5. Calls `client.connect()`.
        6. Calls `client.listTools()` and stores the result.
        7. Emits IPC event 'mcp:status-changed'.
    - mcpDisconnect(id) -> kills process cleanly, cleans up client.

  Auto-start: On Electron app `ready`, loop through servers where 
  `autoStart === true` and trigger `mcpConnect(id)`.

SECTION 4: DATABASE SCHEMA & STORAGE
================================================================================

Store MCPServerConfig globally using `electron-store` with safeStorage 
encryption (specifically to protect the `env` field which often contains 
API keys for the servers).
Key structure in electron-store:
  'mcp.servers' -> MCPServerConfig[]

Do not store connection state or tools list in the database; those are 
in-memory only and resolved at runtime.

SECTION 5: NEW IPC CHANNELS SUMMARY (PART 4)
================================================================================

  'mcp:list'             renderer -> main  () -> MCPServerConfig[]
  'mcp:add'              renderer -> main  (config)
  'mcp:update'           renderer -> main  ({ id, patch })
  'mcp:delete'           renderer -> main  ({ id })
  'mcp:connect'          renderer -> main  ({ id })
  'mcp:disconnect'       renderer -> main  ({ id })
  'mcp:status-changed'   main -> renderer  ({ id, status, tools?, error? })
                         // Emitted when connection succeeds, fails, or drops.
