SECTION 0: CONCEPTUAL INTRODUCTION FOR BEGINNERS
================================================================================

WHAT IS SPECULATIVE EXECUTION?
In standard AI IDEs, you type a prompt ("Fix this error"), hit Enter, and then 
stare at a loading spinner for 30 seconds while the AI thinks. That is slow.

Speculative Execution is how modern CPUs work. The IDE "guesses" what you are 
going to do next based on your current context. 
Example: You paste an error log into the terminal. Before you even open the 
Chat Panel to ask "How do I fix this?", the ZezenexCoderr Speculative Watcher has 
already noticed the error, silently sent it to the Swarm, and the Swarm has 
already written the fix. 
When you finally press Ctrl+Space or open the chat, the answer appears in 
0.01 seconds. It feels like time travel because the AI solved the problem 
in the past.

HARDWARE CONSTRAINT:
Running a Swarm in the background can freeze a computer. The Speculative Watcher 
MUST check the CPU/RAM idle state. It only triggers a "Shadow Run" if the user 
has stopped typing for at least 3 seconds, and it immediately aborts the shadow 
run if the user starts heavily compiling or running local servers.

  Pass this to `speculativeHandler.js` via IPC.

SECTION 3: SHADOW SWARM RUNS & CPU YIELDING
================================================================================

Goal: Run the AI invisibly, but respect the user's hardware.

3.1 speculativeHandler.js (electron/handlers/)
  - Require Node's `os` module to check `os.loadavg()` and `os.freemem()`.
  - If CPU usage is > 70%, ABORT the shadow run (do not steal resources).
  - If safe, dispatch the intent to `swarmHandler.js` (from Part 1) but flag 
    it as `isShadowRun: true`.
  
3.2 Shadow Swarm Adjustments
  - When `isShadowRun === true`, the Swarm does NOT emit `swarm:internal-msg` 
    events to the UI. The SwarmChatPanel remains completely empty.
  - The Swarm skips the "User Approval" handoff. Instead, it packages the 
    final Consensus (Code + Plan) and emits a `speculative:cache-ready` event.

3.3 speculativeStore.js
  - Receives the `cache-ready` event.
  - Stores it: 
    ```js
    cache: { 
      [triggerHash]: { 
        code: "function new()...", 
        explanation: "Fixed the null pointer...",
        timestamp: 169000000 
      } 
    }
    ```

SECTION 4: GHOST TEXT & INSTANT DIFF UI
================================================================================

Goal: Serve the pre-computed answer instantly when the user asks for it.

4.1 GhostTextOverlay.jsx (Monaco Editor Integration)
  - If the user's cursor is at the exact line where a `triggerHash` was generated 
    (e.g., right after `// TODO: create user auth`), query `speculativeStore`.
  - If a cached result exists, use Monaco's `inlineCompletions` API to render 
    the code in italic, grayed-out text ahead of the cursor.
  - If user presses `Tab`, instantly accept the code and clear the cache.

4.2 Instant Chat Resolution
  - If the user opens the Chat Panel and types: "Fix the terminal error", 
    the Chat Input will hash the prompt, check `speculativeStore`, and if a 
    match exists (e.g., an error was just cached from Trigger B), it Bypasses 
    the LLM entirely.
  - Instantly print the cached Swarm response to the Chat Panel (0ms latency) 
    and show the Phase 2A Review Button.
  - Add a tiny visual badge to the message: "⚡ Served from Predictive Cache".
