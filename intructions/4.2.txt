SECTION 0: CONCEPTUAL INTRODUCTION FOR BEGINNERS
================================================================================

WHAT IS COLLABORATIVE INTELLIGENCE?
In Phase 4 Part 1, you taught the AI to learn from its own mistakes. But what 
if you work in a team of 5 people? If Dev A fixes a bug, Dev B shouldn't have 
to hit the same bug again. 

Collaborative Intelligence is "Collective Learning". Your ZenexCoder instance will 
silently talk to your teammate's ZenexCoder instance. If the AI learns that 
"Always use `bcrypt` instead of `md5`" in this project, it will push that 
"Learned Rule" to the team vault. Dev B's ZenexCoder will automatically pull 
this rule, and the AI will suggest the better fix to Dev B instantly. 

We use End-to-End Encryption (E2EE). The "Shared Knowledge" is encrypted 
with a project-specific key. ZenexCoder acts as a decentralized brain for the team.

Goal: Store the learned rules in a format that can be synced securely.

2.1 encryption.js (src/utils/)

  - When a new rule is learned (Phase 4 Part 1), encrypt it and place it in 
    the sync queue.

================================================================================
SECTION 3: P2P SYNC ENGINE
================================================================================

Goal: Sync the vault between team members.

3.1 p2pSyncHandler.js (electron/handlers/)
  - Leverage the LAN discovery built in Phase 3 Part 5 (Hardware Clustering).
  - Use the existing WebSocket backbone to push "New Rule" events to peers.
  - Sync Algorithm:
    1. Node A (has new rule) broadcasts "Update Available" event.
    2. Node B requests the update.
    3. Node A sends encrypted payload.
    4. Node B decrypts and merges into its `learned_rules` SQLite table.
