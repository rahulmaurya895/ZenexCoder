SECTION 0: CONCEPTUAL INTRODUCTION FOR BEGINNERS
================================================================================

WHAT IS ZERO-TOUCH SELF-HEALING?
Usually, when an app crashes in production, a developer gets a PagerDuty alert 
at 3 AM. They wake up, open their laptop, find the Sentry error log, switch 
their Git branch, try to reproduce the bug, write a fix, run tests, push the 
branch, and open a Pull Request.

With Zero-Touch Self-Healing, the IDE does the 3 AM shift.
1. ZezenexCoderr intercepts the Sentry alert.
2. It silently creates a background folder (Git Worktree) so it doesn't mess 
   up whatever you were currently working on.
3. The Swarm Engine reads the stack trace, finds the exact file in the Vector DB, 
   fixes the code, and writes a test.
4. ZezenexCoderr pushes the fix to GitHub and opens a Pull Request.
5. You wake up at 8 AM. You check your phone. You see: "Critical Prod Bug 
   fixed. PR #402 is awaiting your review." You review the code, click Merge, 
   and go back to sleep. The AI never deploys to prod (for safety); it only 
   prepares the fix.

SECTION 2: PRODUCTION TELEMETRY INGESTION
================================================================================

Goal: Securely fetch crash reports without exposing local ports to the internet.

2.1 Install Dependencies
  Add to package.json: `npm install @octokit/rest axios`

2.2 incidentHandler.js (electron/handlers/)
  - Desktop apps cannot easily receive webhooks safely. Instead, we use Polling.
  - User configures a Sentry API Token and Project ID in `IntegrationSettings.jsx`.
  - `incidentHandler.js` runs a `setInterval` (every 5 mins) to fetch `/api/0/projects/{organization_slug}/{project_slug}/issues/`.
  - Filter for newly surfaced issues (e.g., `isUnhandled: true`, `firstSeen` within last hour).
  - Map the payload to a standard format: `{ id, title, stackTrace, url, timestamp }`.
  - Store these in the SQLite database to avoid duplicate processing.

SECTION 3: AUTONOMOUS WORKTREE & HEALER SWARM
================================================================================

Goal: Isolate the fix in the background without touching the user's active editor.

3.1 autoFixer.js (electron/handlers/)
  When a new critical incident is fetched:
  - Step 1 (Git Isolation): Call `gitWorktreeAdd` (Phase 2B Part 2) to create 
    a background folder: `.zenexcoder_worktrees/fix-sentry-issue-<id>`.
  - Step 2 (Swarm Context): Pass the `stackTrace` to the `swarmHandler.js`.
  - Step 3 (System Prompt override): Inject a specific intent to the Architect:
    "You are debugging a production crash. Below is the stack trace. Analyze 
    it, find the root cause, and hand off to the Coder to implement the fix."
  - Step 4 (QA Requirement): The Swarm SecOps/QA persona MUST write a unit test 
    that fails without the fix and passes with the fix.

3.2 Preventing Runaway AI
  - If the Swarm fails to compile/pass tests after 3 attempts, the `autoFixer` 
    must ABORT the self-healing process. 
  - Mark the incident as `Status: Manual Intervention Required` in the UI.

SECTION 4: AUTO-PR GENERATION (GITHUB INTEGRATION)
================================================================================

Goal: Deliver the fix directly to the team's remote repository.

4.1 githubHandler.js (electron/handlers/)
  - Instantiate Octokit with a user-provided GitHub Personal Access Token (PAT) 
    stored securely in `electron-store` (Phase 1 encryption).
  - Once the Swarm achieves consensus and tests pass in the worktree:
    1. Commit changes: `git commit -m "fix(prod): auto-heal issue <id>"`
    2. Push branch: `git push origin fix-sentry-issue-<id>`
    3. Call Octokit `octokit.rest.pulls.create({ ... })`.
  - The PR Body should be generated by the Architect:
    ```markdown
    ### Autonomous Bug Fix
    **Issue:** Sentry Error #1029 (Null Reference in auth.js)
    **Root Cause:** Found that user object could be null during OAuth redirect.
    **Fix:** Added optional chaining and a fallback error redirect.
    **Tests Added:** Yes.
    ```
