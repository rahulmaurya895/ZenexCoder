SECTION 3: GIT INTEGRATION CORE
================================================================================

Goal: real, working git status/branch/commit support, reusing Phase 1's
DiffViewer for showing changes. Worktree support is explicitly OUT OF
SCOPE for Part 1 (-> Part 2).

3.1 gitHandler.js (electron/handlers/)
  Implement via spawned `git` CLI commands (no native deps) in the
  project's working directory:
    - gitStatus(projectPath)        -> { branch, ahead, behind, staged[],
                                          unstaged[], untracked[] }
    - gitListBranches(projectPath)  -> { current, local[], remote[] }
    - gitCheckoutBranch(projectPath, branchName)
    - gitCreateBranch(projectPath, branchName, fromRef)
    - gitStageFile(projectPath, filePath)
    - gitUnstageFile(projectPath, filePath)
    - gitCommit(projectPath, message)  -> { hash, summary }
    - gitDiff(projectPath, filePath, staged: boolean) -> raw diff string
    - gitLog(projectPath, limit) -> commit[] { hash, message, author, date }

  All commands must:
    - Reject/handle gracefully if projectPath is not a git repo (return
      { isRepo: false } rather than throwing).
    - Sanitize/validate paths — never pass unsanitized user input directly
      into shell strings; use argument arrays with spawn, not exec with
      string concatenation.

3.2 gitStore.js
  {
    isRepo: boolean,
    branch: string,
    ahead: number, behind: number,
    staged: FileChange[], unstaged: FileChange[], untracked: string[],
    refreshStatus(),
    stage(filePath), unstage(filePath),
    commit(message),
    branches: { current, local[], remote[] },
    refreshBranches(), checkout(branchName), createBranch(name, fromRef)
  }

3.3 useGit.js
  Thin wrapper exposing the above via window.electronAPI (preload-exposed
  IPC), with loading/error state per call.

3.4 GitPanel.jsx (new Sidebar tab, icon = Lucide `GitBranch`)
  Layout (reuse Phase 1 panel styling, Surface #141414):
    - Header: current branch name (click -> GitBranchSwitcher dropdown),
      ahead/behind counts as small arrows+numbers
    - "Changes" section: Staged / Unstaged / Untracked file lists, each
      row clickable -> opens DiffViewer (Phase 1) for that file
        - Hover actions: stage (+) / unstage (-) icon buttons
    - GitCommitBox.jsx pinned at bottom: textarea for commit message +
      "Commit" button (disabled if no staged files or empty message)
    - "History" collapsible section below: last N commits from gitLog,
      each row shows short hash, message, relative time

3.5 GitStatusBadge.jsx (StatusBar, Phase 1 right side)
  - Shows: <GitBranch icon> branch-name  •  ●(dirty, amber) or ✓(clean,
    success green)
  - Click -> opens GitPanel.jsx
  - If isRepo === false, badge is hidden entirely.

3.6 GitBranchSwitcher.jsx
  - Dropdown listing local branches (current highlighted) + remote
    branches (grouped under "Remote")
  - "+ New branch" input at top -> gitCreateBranch then checkout
  - Selecting a branch -> gitCheckoutBranch; if uncommitted changes exist,
    show a confirm dialog ("You have uncommitted changes. Checkout
    anyway?") before proceeding — DO NOT silently discard changes.

3.7 Permissions tie-in (reuse Phase 2A)
  - gitCommit -> actionType 'git_commit' (medium risk, follows permission
    mode from Phase 2A's usePermissions.js)
  - gitCheckoutBranch with uncommitted changes, gitCreateBranch that
    deletes/overwrites -> treat as 'git_destructive' only if it would
    discard changes; plain checkout/create with clean tree is low risk.
  - Actual git_push / git reset --hard / worktree operations remain OUT
    OF SCOPE for this part (Part 2 handles worktrees; push UI can be
    added in GitPanel in Part 2 as well, gated the same way).

SECTION 5: NEW IPC CHANNELS SUMMARY (PART 1)
================================================================================

  'git:status'           renderer -> main  -> returns gitStatus result
  'git:branches'         renderer -> main  -> returns gitListBranches result
  'git:checkout'         renderer -> main  ({ branchName })
  'git:create-branch'    renderer -> main  ({ branchName, fromRef })
  'git:stage'            renderer -> main  ({ filePath })
  'git:unstage'          renderer -> main  ({ filePath })
  'git:commit'           renderer -> main  ({ message })
  'git:diff'             renderer -> main  ({ filePath, staged })
  'git:log'              renderer -> main  ({ limit })
  'git:status-changed'   main -> renderer  (push update after any git op
                                             or external file change)
