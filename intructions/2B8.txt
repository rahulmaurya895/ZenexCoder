SECTION 2: BACKGROUND SERVER & PHYSICAL GIT HOOKS
================================================================================

Goal: If a user types `git commit -m "update"` in standard iTerm/Command Prompt, 
ZenexCoder should still intercept it to run the "AI Commit Review" automation.

2.1 localServerHandler.js (electron/handlers/)
  - On app launch, start a basic Node HTTP server on `127.0.0.1` (port auto-assigned).
  - Store the port in a global config.
  - Expose a single POST endpoint: `http://127.0.0.1:<port>/webhook`.
  - When hit, it emits an IPC event to the renderer: `hook:external-trigger` 
    with the payload (e.g., event: 'pre-commit', projectPath).

2.2 hookHandler.js (electron/handlers/)
  - IPC function: `installGitHook(projectPath, hookType)`
    - Validates if `.git` folder exists.
    - Writes a bash script to `.git/hooks/[hookType]` (e.g., pre-commit).
    - The bash script uses `curl` to send a POST request to the 
      localServerHandler's port (saving the port in a `.zezenexcoderr-port` temp file 
      or using an environment variable injected by ZenexCoder's terminal).
    - Make the script executable (`chmod +x`).
    - Script logic: "If ZenexCoder server is reachable, wait for response. If 
      response is 400/reject, abort commit (exit 1). If ZenexCoder is closed, 
      bypass and allow commit (exit 0)."

2.3 App Lifecycle Events
  - Hook into existing stores (projectStore, gitStore, environmentStore).
  - When `activeProject` changes -> trigger `onProjectOpen`.
  - When `gitStore.branch` changes -> trigger `onBranchChange`.

SECTION 4: PERMISSIONS GATING (PHASE 2A TIE-IN)
================================================================================

Goal: Hooks execute automatically in the background. They must respect Phase 2A 
permissions.

4.1 automationStore & useAgentRun Integration
  - When a hook triggers, it creates an agent run in the background.
  - If the hook attempts a file_write or git_destructive action, and the 
    global Permission Mode is "Default", it will HALT and show an ApprovalRequest 
    card[cite: 153].
  - If it is a Git Hook (e.g., pre-commit) and it halts for approval, the 
    bash script will "hang" (wait) until the user clicks Approve/Deny in ZenexCoder. 
    If denied, the local server returns 400, and the bash script aborts the commit.

SECTION 5: NEW IPC CHANNELS SUMMARY (PART 8)
================================================================================

  'hook:install-git-hook'   renderer -> main  ({ projectPath, hookType })
  'hook:remove-git-hook'    renderer -> main  ({ projectPath, hookType })
  'hook:external-trigger'   main -> renderer  ({ event, projectPath, payload })
  'hook:resolve-trigger'    renderer -> main  ({ triggerId, status: 'allow'|'block' })
                            // Used to tell the waiting Express server to 
                            // release the curl request from the bash script.
