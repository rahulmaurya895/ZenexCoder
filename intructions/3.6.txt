SECTION 0: CONCEPTUAL INTRODUCTION FOR BEGINNERS
================================================================================

WHAT IS REALTIME FULL-DUPLEX AUDIO?
Phase 2B Dictation was "Half-Duplex": 
1. You click the mic. 2. You speak. 3. You stop. 4. Text is sent. 5. AI replies.

"Full-Duplex" means both you and the AI can speak and listen at the EXACT SAME TIME.
Imagine you are typing code and you say out loud: "Jarvis, change the loop to a map."
The AI instantly says: "Sure, updating the map function, but wait, the array 
might be null." 
You interrupt the AI mid-sentence: "Ah right, add a null check first."
The AI stops talking instantly, registers the interruption, and says: "Added."

To do this, we don't send text. We stream raw PCM audio bytes continuously 
over a WebSocket. We use Voice Activity Detection (VAD) to mute the AI the 
millisecond you start speaking.

SECTION 2: AUDIO PIPELINE & VOICE ACTIVITY DETECTION
================================================================================

Goal: Capture mic audio, detect speech, and play AI audio with zero latency.

2.1 useRealtimeAudio.js (src/hooks/)
  - Request mic permissions using `navigator.mediaDevices.getUserMedia({ audio: true })`.
  - Use `AudioContext` and a `ScriptProcessorNode` (or `AudioWorklet`) to capture 
    raw PCM audio at 24kHz.
  - Send this audio in chunks (e.g., every 100ms) to the main process via a 
    high-frequency IPC channel: `voice:pcm-chunk-out`.
  - Listen for `voice:pcm-chunk-in` from the AI, decode it, and play it through 
    a destination node.

2.2 realtimeClient.js (electron/handlers/)
  - Maintain a persistent WebSocket connection to the AI provider.
  - When the AI generates audio, stream it down to the renderer.
  - VAD (Interruption): If the WebSocket sends an `input_audio_buffer.speech_started` 
    event, it means the AI heard YOU speak. Immediately flush the AI's playback 
    buffer so the AI "shuts up" instantly.

SECTION 3: CONTEXTUAL VOICE STREAMING (EDITOR SYNC)
================================================================================

Goal: The AI must know what you are looking at while you talk.

3.1 Context Updates
  - In a standard chat, you send code when you hit "Enter". In voice mode, 
    there is no "Enter" button.
  - Use a debouncer on the Monaco Editor `onChange` event (from Phase 1).
  - Every time the user stops typing for 1 second, silently send a JSON event 
    over the Realtime WebSocket:
    ```json
    {
      "type": "conversation.item.create",
      "item": {
        "type": "message",
        "role": "system",
        "content": [{ "type": "text", "text": "User is currently looking at file src/auth.js: \n\n <code_state>" }]
      }
    }
    ```
  - Now, if the user says "What does this line do?", the AI already has the code 
    in its real-time context buffer.

3.2 Tool Calling (Swarm Integration)
  - The Realtime API supports function calling. Pass the Phase 3 Part 1 `PERSONAS` 
    as tools.
  - If the user says "Jarvis, write a test for this", the Realtime API will trigger 
    a `tool_call` to the `SecOps` Swarm Agent.
  - The AI will literally say: "Passing this to the QA agent now," while the 
    background Swarm does the heavy lifting.

SECTION 5: NEW IPC CHANNELS SUMMARY (PHASE 3 - PART 6)
================================================================================

  'voice:connect'            renderer -> main  ({ provider, apiKey })
  'voice:disconnect'         renderer -> main  
  'voice:pcm-chunk-out'      renderer -> main  ({ pcmData }) // High frequency
  'voice:pcm-chunk-in'       main -> renderer  ({ pcmData }) // High frequency
  'voice:state-change'       main -> renderer  ({ state: 'listening'|'speaking'|'idle' })
  'voice:context-update'     renderer -> main  ({ filePath, content })

SECTION 7: FINAL INSTRUCTIONS TO CODEX
================================================================================

1. Build on top of EXISTING Phase 1, 2, and 3 (Parts 1-5) codebase.
2. AUDIO PERFORMANCE: IPC can bottleneck if you send thousands of tiny messages 
   a second. Buffer the PCM data into reasonable chunks (e.g., 50ms-100ms) 
   before crossing the IPC bridge from renderer to main.
3. MEMORY LEAKS: AudioContext and WebSocket listeners are notorious for memory 
   leaks. Ensure `voice:disconnect` forcefully closes the WS, stops all media 
   tracks (`track.stop()`), and suspends the AudioContext.
