SECTION 0: CONCEPTUAL INTRODUCTION FOR BEGINNERS
================================================================================

WHAT IS A SEMANTIC KNOWLEDGE GRAPH?
Standard search is "Lexical" (Ctrl+F). If you search "auth", it only finds the 
exact word "auth". 
Semantic search understands meaning. If you ask the AI, "Where do we handle 
user login failures?", the Vector Database mathematically calculates the "distance" 
between your question and the code, returning the `rateLimiter.js` file even if 
the word "login" isn't strictly in that file.

WHY "ON STEROIDS"?
Because we aren't just indexing code. Since we built the MCP Server integration 
in Phase 2B, we can ask the Slack MCP server: "Give me the last 50 messages in 
the #dev channel." We embed those messages. Now, if you type: 
"Fix the database timeout bug Sarah found," the AI searches its Vector DB, 
finds Sarah's Slack message containing the stack trace, finds the exact 
database connection file in your codebase, and sends BOTH to the Swarm Architect 
before writing a single line of code. It feels like magic.

SECTION 2: EMBEDDED VECTOR DATABASE & EMBEDDER
================================================================================

Goal: A robust, local storage mechanism for mathematical arrays (vectors).

2.1 Install Dependencies
  Add to package.json: `npm install vectordb` (LanceDB SDK - runs natively).

2.2 embedderHandler.js (electron/handlers/)
  - We need a local embedding model. Require the user to pull `nomic-embed-text` 
    via the Phase 1 Ollama Manager. (Size: ~270MB. Extremely fast).
  - Function: `generateEmbedding(text)` -> POST to `http://localhost:11434/api/embeddings`
  - Returns an array of floats (e.g., length 768 or 1024 depending on model).

2.3 vectorDbHandler.js (electron/handlers/)
  - Initialize LanceDB in the user's `.nexcode_data/vector_db/` directory.
  - Create two primary tables (collections):
    1. `code_chunks`: 
       Schema: { id, project_path, file_path, content, vector, last_modified }
    2. `external_memory`: 
       Schema: { id, source (e.g., 'slack', 'jira'), url, content, vector, timestamp }

SECTION 3: BACKGROUND INDEXER (THE CRAWLER)
================================================================================

Goal: Keep the Vector DB up to date without freezing the UI.

3.1 indexerDaemon.js (electron/handlers/)
  - Listen for the `projectOpened` event (Phase 1 / Phase 2B).
  - Run a delta sync:
    1. Scan the project directory. Ignore `.git`, `node_modules`, and files in `.gitignore`.
    2. Compare file `last_modified` timestamps with the DB.
    3. If new/changed: Read file -> Send to `textSplitter.js` -> Get array of chunks.
    4. Batch process embeddings (e.g., 10 chunks at a time).
    5. Upsert into LanceDB.
  
3.2 MCP Data Ingestion
  - If MCP Servers (Phase 2B) are connected, and the user has toggled "Index External 
    Data" in the KnowledgePanel:
    1. Query the MCP server's exposed tools (e.g., `github_list_issues`, `slack_read_channel`).
    2. Fetch the text data.
    3. Chunk, embed, and store in the `external_memory` table.

3.3 CPU/RAM Management
  - Embedding is intensive. The indexer must yield to the event loop. Pause 
    indexing if the LLM is actively generating code for the Swarm to prevent 
    hardware lockup on 8GB machines.

SECTION 4: RAG INJECTION ENGINE (AGENT INTEGRATION)
================================================================================

Goal: Feed the Swarm the exact context it needs before it starts thinking.

4.1 swarmHandler.js (Phase 3 Part 1 EXTENSION)
  - Intercept the `USER` prompt before passing it to the `ARCHITECT`.
  - Step 1: Embed the user's prompt via `embedderHandler.js`.
  - Step 2: Query LanceDB `code_chunks` table for the top `K=5` closest vectors 
    using cosine similarity or L2 distance.
  - Step 3: Query LanceDB `external_memory` for the top `K=3` closest vectors.
  - Step 4: Inject this data into the Architect's System Prompt dynamically:
  
  User Request: {User Prompt}

  --- AUTOMATIC CONTEXT RETRIEVAL (RAG) ---
  The following code snippets and external memory might be relevant:
  <CodeSnippet file="src/api/auth.js">
    {content}
  </CodeSnippet>
  <ExternalMemory source="slack_mcp">
    [Sarah]: Hey, the login route in src/api/auth.js throws a 500 timeout error.
  </ExternalMemory>
  -----------------------------------------
  Based on this context and the user request, draft your architectural plan.
