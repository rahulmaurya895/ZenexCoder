SECTION 0: CONCEPTUAL INTRODUCTION FOR BEGINNERS
================================================================================

WHAT IS LOCAL HARDWARE CLUSTERING?
Let's say you are sitting on your couch coding on a lightweight MacBook Air (8GB RAM). 
Running a local AI model on it drains the battery in 45 minutes and makes the 
laptop overheat. However, in your bedroom, you have a massive Windows Gaming PC 
with an RTX 4090 GPU just sitting idle.

Clustering bridges them. Both run ZenexCoder. 
When you type a prompt on your MacBook, the MacBook sends the prompt over your 
WiFi to the Gaming PC. The PC's massive GPU processes the AI thought 10x faster 
than the Mac ever could, and sends the text stream back to your MacBook's screen.
To the user, it feels like the MacBook suddenly gained a supercomputer's power. 
No cloud fees, no internet latency, complete privacy.

SECTION 2: LAN DISCOVERY & SECURE PAIRING
================================================================================

Goal: Find devices effortlessly but prevent random people on a Starbucks WiFi 
from hacking your desktop.

2.1 Install Dependencies
  Add to package.json: `npm install bonjour-service ws`

2.2 networkDiscovery.js (electron/handlers/)
  - On app start, broadcast a Bonjour service: 
    `{ name: 'ZenexCoder-Node-' + os.hostname(), type: 'zezenexcoderr', port: 44556 }`
  - Simultaneously scan for `_zezenexcoderr._tcp`. Emit `cluster:node-found` to the UI 
    when a new machine appears on the LAN.

2.3 Secure Handshake (websocketServer.js & Client)
  - When the user clicks "Connect" on the MacBook (Master), it initiates a 
    WebSocket connection to the PC (Worker).
  - The PC shows a system toast: "MacBook-Air is trying to connect. PIN: 849201".
  - The user types `849201` into the MacBook's `PairingModal.jsx`.
  - Upon success, upgrade the connection to use AES-256 encryption using a 
    shared session key.

SECTION 3: AI OFFLOADING ROUTER
================================================================================

Goal: Hijack the Ollama API calls and send them across the room.

3.1 ollamaService.js (Phase 1 EXTENSION)
  - Modify the base URL configuration. 
  - Instead of hardcoding `http://localhost:11434`, check `clusterStore`.
  - If a Worker node is connected and marked as "Primary GPU", the `ollamaService` 
    should send the request to `websocketClient.js`, which wraps the payload and 
    sends it to the Worker.
  - The Worker receives the payload, makes the HTTP call to its OWN local Ollama 
    instance, and streams the chunks back over the WebSocket.
  - The Master receives the chunks and updates the UI exactly as if it was local.

3.2 Distributed Swarm (loadBalancer.js)
  - During a Swarm Run (Phase 3 Part 1), the Master node can split tasks.
  - While the remote Worker node (RTX 4090) generates the heavy Coder output, 
    the local Master node (MacBook) can simultaneously run the lighter Architect 
    planning model.
