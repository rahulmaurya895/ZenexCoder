SECTION 2: BROWSER ENGINE & AGENT TOOLS
================================================================================

Goal: The AI needs to search documentation, read GitHub issues, or debug 
web apps visually. We use Playwright to drive this.

2.1 Install Dependencies
  Add to package.json: `npm install playwright`

2.2 browserHandler.js (electron/handlers/)
  Maintain a singleton Playwright browser instance.
  IPC-exposed functions:
    - browserStart() -> Launches Chromium.
    - browserStop() -> Closes browser.
    - browserNavigate(url) -> Goto URL, wait for 'domcontentloaded'.
    - browserClick(selector) -> Playwright `.click(selector)`.
    - browserType(selector, text) -> Playwright `.fill(selector, text)`.
    - browserGetDOM() -> Returns an accessibility tree or simplified Markdown 
      representation of the DOM (easier for LLMs to read than raw HTML).
    - browserGetScreenshot() -> Returns base64 image of the viewport.

2.3 AI Service Injection (openaiService.js / anthropicService.js)
  Add these built-in tools to the LLM payload (similar to MCP tools in Part 5):
    - `browser_navigate`: { url: string }
    - `browser_click`: { element_id_or_selector: string }
    - `browser_type`: { element_id_or_selector: string, text: string }
    - `browser_read_page`: {} -> Returns the markdown-simplified DOM.

  Update the System Prompt:
  "You have access to a web browser. Use 'browser_navigate' to open URLs, 
   'browser_read_page' to understand the layout, and 'browser_click'/'browser_type' 
   to interact. Always read the page before interacting."

SECTION 3: THE BROWSER UI PANEL
================================================================================

Goal: The user must see what the AI is doing. Blind web browsing is a security risk.

3.1 BrowserPanel.jsx (Connections Hub slide-over or Sidebar tab)
  Layout:
    - Top: BrowserToolbar.jsx
    - Main: BrowserViewport.jsx
  
3.2 BrowserToolbar.jsx
  - Back, Forward, Reload buttons (wired to IPC).
  - Address Bar (read-only when AI is controlling, but user can type to 
    manually navigate).
  - "Close Session" button (Error red outline) to forcefully kill the 
    Playwright instance.

3.3 BrowserViewport.jsx
  - Since embedding Playwright directly into a React UI is complex, use the 
    Screenshot Streaming approach (industry standard for agent UIs):
    Whenever the DOM changes or the agent takes an action, `browserHandler` 
    emits a base64 screenshot via IPC 'browser:frame-update'.
  - Render an `<img src="data:image/jpeg;base64,..." />` that fills the viewport.
  - Show a loading spinner overlay when `browserStore.isLoading === true`.

SECTION 4: PERMISSIONS GATING (PHASE 2A TIE-IN)
================================================================================

Goal: Web browsing can trigger side effects (submitting forms, deleting data).

4.1 approvalRules.js (Phase 2A) — EXTEND
  Add new rules:
  - actionType: 'browser_read' (Includes `Maps`, `read_page`)
    riskLevel: 'low' (Executes automatically, no prompt).
  - actionType: 'browser_interact' (Includes `click`, `type`, `submit`)
    riskLevel: 'medium' (Follows permission mode. Ask in "Default", auto-run 
    in "Auto-review").

4.2 agentHandler.js / useAgentRun.js — EXECUTION
  When the agent requests `browser_click`:
  1. Trigger ApprovalRequest card.
  2. Text: "AI wants to click on [selector] at [Current URL]".
  3. Include the latest viewport screenshot in the Approval card so the user 
     can visually verify what the AI is about to click.
  4. On Approve -> call `browserHandler.browserClick()`.

SECTION 5: NEW IPC CHANNELS SUMMARY (PART 6)
================================================================================

  'browser:start'          renderer -> main
  'browser:stop'           renderer -> main
  'browser:navigate'       renderer -> main  ({ url })
  'browser:click'          renderer -> main  ({ selector })
  'browser:type'           renderer -> main  ({ selector, text })
  'browser:get-dom'        renderer -> main  () -> Returns simplified DOM string
  'browser:nav-changed'    main -> renderer  ({ url, title, isLoading })
  'browser:frame-update'   main -> renderer  ({ base64Image })

================================================================================

1. Build on top of EXISTING Phase 1 + 2A + 2B (Parts 1-5) codebase.
2. DOM Simplification is CRITICAL. Do not pass raw HTML to the LLM (it will

   inputs, buttons, and links. Map them to a clean format: 
   `[Button: Submit] (id: submit-btn)`.

   quits. Orphaned Chromium instances will consume severe RAM.
