SECTION 0: CONCEPTUAL INTRODUCTION FOR BEGINNERS
================================================================================

WHAT IS SYNTHETIC QA?
Usually, developers write "Unit Tests" (checking if a function returns 5 when 
you add 2+3). But bugs often happen at the "User Level" (e.g., button is 
hidden behind a popup).

Synthetic QA = "Robot Users".
Hum background mein headless browser (bina UI wala chrome) chalayenge. Yeh agent 
tumhari website par jayega, login karega, form bharega, aur check karega ki 
sab sahi se ho raha hai ya nahi. Agar "Checkout" button nahi dikha, toh agent 
turant report karega: "UI Regression detected: Checkout button missing."

SECTION 3: VISUAL REGRESSION ENGINE
================================================================================

Goal: Catch UI changes that look broken to a human.

3.1 visualDiffEngine.js (electron/handlers/)
  - During test execution, take screenshots of critical pages.
  - Store "Golden Snapshot" (the expected look) in `tests/visual/`.
  - Compare new screenshot vs Golden Snapshot using pixel-matching (e.g., `pixelmatch` library).
  - If mismatch > 5%, mark as "Visual Regression".

================================================================================
SECTION 4: FLAKY TEST AUTO-REPAIR
================================================================================

Goal: Agents that fix their own tests.

4.1 Self-Healing Integration
  - If Playwright throws `ElementNotFoundException`:
    1. Send DOM snapshot to the Swarm (Phase 3 Part 1).
    2. Prompt: "Selector for #submit-btn is invalid. Given this DOM tree, what is the new selector?"
    3. Update test script dynamically.

SECTION 8: FINAL INSTRUCTIONS TO CODEX
================================================================================

1. Performance: Headless browsers are memory-heavy. Limit to 1 active agent 
   at a time on 8GB RAM machines.
2. Stability: Always use `page.waitForSelector()` to avoid race conditions. 
   Do not hardcode `wait(1000)` timeouts—they make tests flaky.
3. Isolation: These tests must NOT run against real Production environments 
   without explicit user permission. Default to `localhost` or `staging`.
