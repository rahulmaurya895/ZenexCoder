SECTION 2: AGENT ENVIRONMENT (WINDOWS NATIVE SANDBOX)
================================================================================

Goal: AI agents running `rm -rf` or executing untrusted code should do so in an 
ephemeral environment. We will use Windows Sandbox (built into Windows 10/11 Pro).

2.1 sandboxHandler.js (electron/handlers/)
  - IPC function: `sandboxStart(projectPath)`
    - Generates a dynamic `.wsb` (Windows Sandbox configuration) XML file.
    - Uses `<MappedFolders>` to mount the current `projectPath` into the Sandbox 
      as Read/Write.
    - Uses `<LogonCommand>` to inject a small ZenexCoder listener script into the 
      Sandbox so the main app can send terminal commands into the VM.
    - Spawns the Sandbox using `child_process.exec('start "" "zezenexcoderr_temp.wsb"')`.
  - IPC function: `sandboxStop()`
    - Kills the sandbox process.

2.2 Agent Execution Routing (agentHandler.js EXTENSION)
  - Before executing a step of type `terminal_run`, check `envIsolationStore`.
  - If `isolation === 'windows_sandbox'`, route the command to the Sandbox 
    listener instead of the local `node-pty` instance.
  - If `isolation === 'host'`, run normally.

2.3 AgentEnvPanel.jsx
  - UI Toggle: "Run Agent in Isolated Sandbox".
  - Warning note: "Requires Windows 10/11 Pro/Enterprise with Windows Sandbox 
    feature enabled. The agent will mount your project folder but cannot harm 
    your host OS."

SECTION 3: TERMINAL SHELL SELECTOR
================================================================================

Goal: Users need control over the underlying shell used by `node-pty`.

3.1 terminalHandler.js (Phase 1 EXTENSION)
  - Currently hardcoded to `bash` or `powershell`.
  - Add IPC: `terminalSetShell(shellPath)`
  - Provide a utility `detectAvailableShells()`:
    - Windows: `powershell.exe`, `cmd.exe`, `C:\Program Files\Git\bin\bash.exe`, `pwsh.exe`
    - Mac/Linux: `/bin/zsh`, `/bin/bash`
  - Update the `node-pty` spawn logic to use the configured shell path.

3.2 ShellSelector.jsx
  - Placed in the Terminal Panel header (Phase 1).
  - A dropdown listing detected shells + "Custom Path...".
  - On change, gracefully kill the current `node-pty` instance and respawn 
    it with the new shell, retaining the working directory.

SECTION 4: POPOUT WINDOW & GLOBAL HOTKEY
================================================================================

Goal: Allow the user to press Alt+Space anywhere on their computer to summon 
the ZenexCoder Chat/Agent interface without switching virtual desktops.

4.1 popoutWindow.js (electron/windows/)
  - Create a new `BrowserWindow`:
    - `frame: false`, `transparent: true`, `alwaysOnTop: true`, `skipTaskbar: true`.
    - Dimensions: 400x600.
  - Load the same Vite dev server URL or local HTML, but append a route query: 
    `?window=popout`.

4.2 Global Shortcut (main.js EXTENSION)
  - Use `globalShortcut.register('Alt+Space', () => { ... })`.
  - If popout is hidden, show and focus it at the cursor's current display location.
  - If popout is visible, hide it.

4.3 State Synchronization
  - The Popout Window needs to share `chatStore`, `agentStore`, and `appStore` 
    with the Main Window.
  - Use IPC to broadcast Zustand state changes:
    - Main Window emits `store:sync` -> Main Process -> Popout Window.
    - Popout Window emits actions -> Main Process -> Main Window executes them.
  - PopoutContainer.jsx replaces the standard App layout when `?window=popout` 
    is detected. It renders ONLY the `ChatPanel` and `FollowUpBar`.
