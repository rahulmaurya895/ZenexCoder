SECTION 2: DESKTOP AUTOMATION & AGENT TOOLS
================================================================================

Goal: The AI must be able to view the screen (screenshot) and interact with it 
(x,y coordinates for mouse, string inputs for keyboard) similar to Anthropic's 
Computer Use API.

2.1 Install Dependencies
  Add to package.json: `npm install @nut-tree/nut-js`

2.2 computerHandler.js (electron/handlers/)
  Maintain a strict safety lock. If `isLocked === true`, all commands are ignored.
  IPC-exposed functions:
    - computerGetScreen() -> Returns base64 screenshot of the primary display 
      and screen dimensions (width, height).
    - computerMouseMove(x, y) -> Moves cursor using nut.js.
    - computerMouseClick(button, doubleClick) -> Left/Right/Middle clicks.
    - computerKeyboardType(text) -> Types text using nut.js.
    - computerKeyboardPress(keys) -> For shortcuts (e.g., ['Control', 'C']).
    - computerLock() -> The Kill Switch. Instantly sets `isLocked = true`.
    - computerUnlock() -> Re-enables control.

2.3 AI Service Injection (openaiService.js / anthropicService.js)
  Add these built-in tools to the LLM payload:
    - `computer_screenshot`: {} -> Returns base64 image + screen dimensions.
    - `computer_mouse_action`: { action: "move"|"click"|"double_click", x?: number, y?: number, button?: "left"|"right" }
    - `computer_keyboard_type`: { text: string }
    - `computer_keyboard_shortcut`: { keys: string[] }

  Update the System Prompt:
  "You have full desktop access. Use 'computer_screenshot' to view the screen 
   and find exact coordinates. Move the mouse to those coordinates, then click. 
   Type carefully. If you lose track, take another screenshot."

SECTION 3: THE COMPUTER USE UI PANEL
================================================================================

Goal: A dashboard to enable/disable this dangerous feature and monitor logs.

3.1 ComputerUsePanel.jsx (Connections Hub slide-over or Sidebar tab)
  Layout:
    - Top: Master Enable/Disable Toggle. (If disabled, AI tools are hidden 
      from LLM context).
    - Main: ComputerActionLog.jsx showing a live feed:
        `[14:02:01] 📸 Took screenshot (1920x1080)`
        `[14:02:05] 🖱️ Moved mouse to (450, 890)`
        `[14:02:06] 🖱️ Left Click`
        `[14:02:09] ⌨️ Typed "npm run start"`
    - Bottom: EmergencyStopButton.jsx.

3.2 EmergencyStopButton.jsx
  - A large, highly visible button (Background: Error red #EF4444).
  - Text: "EMERGENCY STOP (Esc x3)".
  - Clicking this OR pressing Escape 3 times globally:
      1. Calls `computerHandler.computerLock()`.
      2. Calls `agentStore.stop()` (Phase 2A) to abort the current AI run.
      3. Shows a massive system toast: "AI CONTROL TERMINATED".

SECTION 4: PERMISSIONS GATING (PHASE 2A TIE-IN)
================================================================================

Goal: OS-level control is a massive security risk. It requires the highest 
level of consent.

4.1 approvalRules.js (Phase 2A) — EXTEND
  Add new rules:
  - actionType: 'computer_screenshot'
    riskLevel: 'medium' (Executes automatically in Auto-review/Full access, 
    prompts in Default).
  - actionType: 'computer_interact' (Mouse & Keyboard)
    riskLevel: 'high' (Treat similarly to `git_destructive`). 
    Even in "Full Access", the user MUST explicitly check a box in the 
    Computer Use Panel saying "Allow unattended mouse/keyboard control for 
    this session" before it can bypass the per-action approval prompt.

4.2 ApprovalRequest.jsx (Phase 2A) — EXTEND
  If an approval is triggered for `computer_interact`:
  - Show warning: "AI wants to take control of your mouse/keyboard."
  - Show the intended action (e.g., Move to X: 500, Y: 200).
