SECTION 0: CONCEPTUAL INTRODUCTION FOR BEGINNERS
================================================================================

WHAT IS ENTERPRISE GOVERNANCE?
In a big company, you can't just let an AI write and deploy code without 
oversight. You need "Guardrails". 
- "Audit Log" is like an airplane's black box—it records everything the AI does, 
  so if something breaks, you know exactly when the AI changed the code.
- "Policy Engine" is the bouncer—if the AI tries to write a password in plain text 
  in a file, the Bouncer catches it before it gets saved.
- "Compliance Scanner" is the lawyer—it checks that your code doesn't use libraries 
  that have legal or security risks.

SECTION 2: IMMUTABLE AUDIT LOG
================================================================================

Goal: A permanent, encrypted record of every AI action.

2.1 auditLogHandler.js (electron/handlers/)
  - Every time an agent (Swarm) proposes a change, `auditLogHandler` writes 
    an entry to `audit.log.enc`: 
    `{ timestamp, agent_id, action, file_path, diff, approval_status }`.
  - Use `fs.appendFile` to ensure it's "append-only". This cannot be edited 
    or deleted by the user without manual, high-privilege access.

================================================================================
SECTION 3: THE POLICY ENGINE (THE "BOUNCER")
================================================================================

Goal: Block dangerous actions before they happen.

3.1 policyEnforcer.js (electron/handlers/)
  - This acts as a Middleware in the Swarm loop.
  - Before any code is committed to disk (Phase 2A Approval), pass it through 
    the `policyEnforcer`.
  - Rule Examples:
    - `no_secrets`: Regex check for `API_KEY`, `PASSWORD`, etc.
    - `no_eval`: Block use of `eval()` or `new Function()`.
    - `no_external_ip`: Block requests to unknown public IPs.
  - If a violation is found: ABORT the agent run and return: 
    "Policy Violation: {RuleName}. Fix this code before approval."

================================================================================
SECTION 4: COMPLIANCE SCANNER
================================================================================

Goal: Protect the company from legal/security debt.

4.1 complianceScanner.js (electron/handlers/)
  - Periodically scan `package.json` against the OSV (Open Source Vulnerabilities) 
    database API.
  - Scan for licenses (MIT, Apache, GPL).
  - Report findings to `ComplianceReport.jsx`.
