SECTION 0: CONCEPTUAL INTRODUCTION FOR BEGINNERS
================================================================================

WHAT IS CI/CD AUTOPILOT?
CI (Continuous Integration) = Code merging & testing.
CD (Continuous Deployment) = Pushing to production.
Autopilot = The AI does all this for you.

Usually, you need DevOps engineers to write complex YAML files for GitHub Actions.
With ZenexCoder, you just say: "Deploy this Node.js app to Vercel."
The AI generates the config files, creates the infrastructure, sets up the 
pipeline, and handles the deployment. If the deployment fails (e.g., 500 Error), 
it detects the spike in errors and rolls back the deployment instantly. 
It's like having a DevOps engineer inside your IDE.

SECTION 2: INFRASTRUCTURE-AS-CODE (IaC) GENERATION
================================================================================

Goal: Automatically describe the infrastructure needed.

2.1 iacGenerator.js (src/utils/)
  - When the user asks to deploy:
    1. AI analyzes `package.json` to detect runtime (Node, Python, etc.).
    2. AI scans for environment variables (e.g., `.env.example`).
    3. Generate a `main.tf` (Terraform) or `serverless.yml` config file inside 
       the project's `.zezenexcoderr/deploy/` folder.

================================================================================
SECTION 3: CLOUD PIPELINE ORCHESTRATOR
================================================================================

Goal: Automate the deployment loop.

3.1 cicdHandler.js (electron/handlers/)
  - Step 1: Run local tests (via `npm test`).
  - Step 2: If pass, call `cloudProviderBridge.js`.
  - Step 3: Trigger `terraform apply` (using the generated config).
  - Step 4: Health Monitor: After deploy, check deployment URL for 200 OK.
  - Step 5: Rollback Logic: If 200 OK is NOT received, execute `terraform destroy` 
    or rollback to previous Git ref.

================================================================================
SECTION 4: AUTO-ROLLBACK ENGINE
================================================================================

Goal: Detect failure and recover instantly.

4.1 healthMonitor.js (electron/handlers/)
  - Maintain a persistent monitor (using `setInterval`).
  - If deployment status is `Live`, ping the production URL every 30 seconds.
  - If it returns > 5% error rate or latency > 2s:
    - Trigger `cicdHandler:rollback`.
    - Notify user: "Deployment unhealthy. Rolling back to commit hash <ID>."
